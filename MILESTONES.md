# OpenRatchet milestones

This file is the concise source of truth for current development. Historical
PS2Runtime/GS-first investigations remain in Git history; the project has now
pivoted to a native-port architecture.

Status values: `DONE`, `IN PROGRESS`, `TODO`.

## Active work

### Current milestone

M3 — Native VFS / asset access.

### Phase-3 change under verification

- Added `assets::decompressWad`, a bounded host implementation of the R&C1 WAD
  packet semantics exercised by guest function `0x20b618`.
- The first real shadow run proved the previous boot source was truncated: the
  game reached `0x20b618` with `input=0x1ff8000` while the encoded stream declared
  `0x50e0f` bytes. Generated `sub_00201650` shows the WAD buffer is sized from
  the disc TOC immediately before the second sector read.
- Generated `FUN_0012f2b8` is the actual owner of that TOC state: it requests a
  0x2960-byte table through SIF and copies it to `0x137b80`, overwriting the two
  WAD2/0 fields that an earlier timing fix tried to publish independently.
- OpenRatchet now replaces `0x12f2b8` with a native disc-TOC loader backed by
  `build/toc.json`. On the retail table, WAD2/0 is reconstructed at offsets
  `0x12c0/0x12c4` as sector `0x3809`, count `0xa2`; the caller should therefore
  place the complete WAD around `0x1fa7000` and the native sector reader can load
  all `0x51000` bytes directly from `wads2/0`.
- The extraction wrapper now exports the final 38 level-directory locations too.
  Existing JSON generated by the old wrapper remains accepted; its exact
  0x28c8-byte known prefix is used and its missing 0x98-byte tail is zero-filled.
- The complete boot WAD then exposed that the legacy `0x20b618` SPR/DMAC bridge
  is not a valid oracle: it reports `0x8f4600` decompressed bytes while the native
  decoder returns `0xa346c` bytes. The native result has a coherent 0xc0-byte
  24-entry archive directory whose final payload ends exactly at `0xa346c`.
- The native decoder was independently cross-checked against the known Ratchet
  WAD packet algorithm. On the uploaded/extracted WAD2 corpus it agrees for all
  249 compressed WAD streams across 165 files, totaling `0x20f312c` output bytes.
  The tests now preserve that corpus result as an aggregate regression manifest.
- The legacy decompressor remains in the runtime only so Phase 3 stays
  non-mutating. Its output is diagnostic debt, not the correctness authority.

### Acceptance test

A Release build and all six CTest tests must pass. A 20-second native diagnostic
must remain alive and preserve graphics activity. The native storage path must
show all of the following:

```text
[OpenRatchet:VFS] native disc TOC ... destination=0x137b80 bytes=0x2960 ...
[OpenRatchet:VFS] native sector read ... source=0x3809 sectors=0xa2 destination=0x1fa7000 ... asset=wads2/0
```

The old `legacy boot alias destination=0x1ff8000` line must disappear. The WAD
shadow must reach the complete stream and report the independently established
native oracle:

```text
[OpenRatchet:WAD] shadow ... nativeBytes=0xa346c nativeHash=0xd3cb9822 status=ok oracle=match legacyMatch=0
```

`legacyMatch=0` is expected in this phase and records the bug in the compatibility
bridge that is about to be removed. The `wad_decompressor` CTest must also pass
its real boot fixture and WAD2 corpus manifest. Replacement registration should
be `bootstrap=2`, `runtime=10`, with zero installation errors.

### Next phase after acceptance

Make the native decoder the owner of `0x20b618` and delete the decompressor-
specific scratchpad/SPR-DMAC bridge from `guest_overrides.cpp`. That converts
another PS2 hardware dependency into a game-semantic native service without
touching generated EE source.
